# 真实收款开启前检查表

这份文档只回答一件事：

什么时候你才可以把项目从“演示/等待模式”切到“真实收款”。

## 一、必须全部满足，才能开真实收款

### 1. 你确认自己真的能收款

必须确认：

- 你的收款主体能通过平台审核
- 你的 payout 路径是真实可用的
- 你知道钱会打到哪里
- 你知道大概多久能到账

如果这一步没确认，不要开 live charging。

### 2. 你的支付链接是真实可用的

必须确认：

- PayPal 支付链接或 hosted checkout link 能打开
- 用户能正常支付
- 支付后能回到站内
- 站内能显示成功状态

### 3. 你的产品交付边界明确

必须确认：

- 用户买到的 ritual pack 包含什么
- 不包含什么
- 是一次性内容还是后续可重复查看
- 用户遇到问题后怎么联系你

### 4. 你的退款口径明确

必须确认：

- 是否支持退款
- 什么情况下退款
- 谁来处理退款
- 多久回复用户

### 5. 页面文案没有高风险承诺

必须确认页面里没有：

- 保证发财
- 保证结果
- 保证关系修复
- 医疗 / 法律 / 金融建议承诺

## 二、建议先做的小范围真测

不要一上来就公开大推。

先做：

- 1 到 3 个真实测试支付
- 自己支付一次
- 让熟人或小范围用户支付一次
- 检查回跳、恢复、状态显示

## 三、如果有任何一项不确定

那就继续用：

```bash
VITE_PAYMENT_PROVIDER=manual_waitlist
VITE_PAYMENT_LINK_MODE=demo
```

先上线验证需求，不要急着收钱。

## 四、真正开收款的标准

只有当下面这些都满足时，才建议你打开真实收款：

- 页面已经稳定
- ritual pack 是主收费入口
- 你能稳定收款
- 你完成过真实支付测试
- 你有最基本的退款和客服口径

推荐优先顺序：

- 先用 `PayPal payment link`
- 后面再评估 `Paddle / Lemon Squeezy`
- 不要把 `Stripe` 作为大陆主体的第一个默认方案

## 五、你当前最现实的原则

不是“能不能做支付”，而是：

- 你能不能真实收到钱
- 你收了钱后能不能稳住体验
- 你出了问题后能不能处理

只要这三件事没有同时成立，就不要切 live。
